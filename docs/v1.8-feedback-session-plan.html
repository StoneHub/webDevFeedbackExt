Dev Feedback Capture · v1.8 plan · July 28, 2026

Reproduce the path, not only the last screen.

A Feedback Session should turn one deliberate browser journey into a compact, reviewable timeline: where the user went, what they interacted with, where capture paused, and which feedback item marks the issue. The first release is structured evidence—not continuous video or hidden surveillance.

Explicit start and stop One target tab Local only Values redacted Review before export

Product decision

Best path: ship a structured timeline MVP now; prove WebM separately later.

Why: a timeline is smaller, searchable, agent-readable, compatible with the extension’s existing feedback bundles, and can redact sensitive values before storage. It directly answers “how did I get here?” without turning the extension into a general screen recorder.

Counterpoint / risk: a timeline will not preserve every animation, hover state, transient overlay, canvas change, or visual timing issue. A user who expects literal playback may call it incomplete. The UI and Store copy must say Feedback Session timeline, never “screen recording,” until a real video path passes its own privacy and runtime gates.

Next step: implement the timeline behind one explicit Start session action, validate it in unpacked Edge and Chrome on a purpose-built test journey, then decide whether a tab-video spike earns v1.9 scope.

Now versus later

v1.8 MVP

Structured feedback timeline

  • Records committed page loads, same-document route changes, reloads, back/forward transitions, and navigation failures for the target tab.
  • Records safe interaction summaries: click, submit, control change, a small allowlist of non-text keys, and debounced scroll checkpoints.
  • Links existing Element, Visual, and Region feedback items to the active session.
  • Shows a persistent recording indicator, duration, event count, scope, pause, and stop.
  • Saves locally in bounded per-session records and exports readable Markdown plus structured JSON.
Optional later

User-triggered WebM tab capture

  • Requires a separate tabCapture permission and explicit user gesture.
  • Likely needs an offscreen document and MediaRecorder because a Manifest V3 service worker cannot own a long-lived DOM media pipeline.
  • Captures tab content, not the browser address bar or all desktop activity.
  • Audio stays off by default; video redaction is a separate unsolved product problem.
  • Must stream to bounded local storage and explicit download—not accumulate in extension history.

The user flow

Name the session

Open the extension, choose Start feedback session, and optionally enter a short goal such as “Checkout failure.”

Confirm scope

See the target tab, current origin, URL-redaction policy, and the exact events that will and will not be stored.

Reproduce

Use the site normally. The badge and popup keep a visible red recording state with elapsed time and event count.

Mark the issue

Use Element, Visual, or Region capture—or add a short marker note. The new feedback item joins the current timeline.

Stop and review

Stop recording, inspect the ordered path, remove irrelevant events, and verify every redaction before export.

Hand off

Download a versioned local JSON timeline or copy a concise Markdown reproduction path after adding the issue summary.

Session scope is one tab, not the whole browser. Switching tabs does not begin collecting from the other tab. If a link opens a new tab, v1.8 remains bound to the original tab and does not silently follow it.

Cross-origin navigation is a visible boundary. The navigation itself may appear in the timeline, but page interaction capture pauses when temporary activeTab access ends. The user can click the extension and explicitly resume on the new site. No broad, permanent all-sites access is required for the MVP.

Honest wording: “Recording” means an ordered structured timeline. The session does not take a screenshot on every action and does not capture pixels continuously.

What the MVP records

Signal Stored detail Guardrail
Session state Start, pause, resume, stop, interruption, derived duration, event count, and truncation state. Only after an explicit user action; one active session at a time.
Navigation Main-frame committed/completed/error events; SPA route and fragment updates; transition type and qualifiers. Store origin + pathname. Remove the complete query string and fragment. Ignore subframe noise in v1.8.
Click Pointer button, semantic target role/tag, bounded label, stable best-effort selector. Bound target text and collect it only from button/link-like controls; input values are never read.
Form intent Submit event, form name or label, and which safe control kinds changed. No field values, autofill content, password content, or serialized form data. Checkbox/radio checked state may be recorded.
Keyboard Only action keys useful for reproduction: Enter, Escape, Tab, arrows, Space, and named shortcuts. Never record printable keys, composition events, key sequences, or clipboard content.
Scroll Debounced final scroll coordinates plus viewport dimensions. No high-frequency pointer or scroll stream; coalesce repeated events.
Never by default Raw keystrokes, field values, passwords, cookies, storage, request/response bodies, headers, tokens, clipboard, microphone, webcam, or continuous screenshots. These are outside the extension’s focused purpose and are not required to reproduce a browser path.

Architecture: one authoritative session controller

Popup + badge Explicit controls, timer, scope, count, paused state.
→
Background session controller Owns one session, tab ID, event sequence, mutation queue, active marker, restart reconciliation, and caps.
↔
Navigation listeners webNavigation and tab lifecycle events, main frame only.
Session content recorder Capture-phase event listeners; semantic summaries only.
→
Local session store One bounded local record per session plus a 20-session index, then review/export.

Static browser listeners

Register Manifest V3 event listeners synchronously in background.js. Each listener exits immediately when no session is active. Do not depend on an in-memory service worker timer to preserve state.

Serialized, bounded writes

Reuse the background mutation-queue pattern. Store each sanitized session separately from visual feedback history, cap it at 1,500 events or 5 MiB, enforce an 8 MiB local-storage safety boundary, and retain only the latest 20 sessions.

Crash and restart truth

Keep the active marker in chrome.storage.session. A service-worker restart preserves it; a browser or extension restart clears it, and reconciliation finalizes any unmatched local recording as interrupted.

Implemented files: session-recorder.js for page events and visible controls, session-model.js for schema/redaction/export, controller helpers in background.js, and the separate sessions.html/sessions.js review surface.

Local data model

Session records use a new schema and new storage prefix. Existing feedback history remains readable and unchanged; direct linkage from Element, Visual, and Region items is deferred.

Size budget: v1.8 retains the latest 20 sessions and caps each one at 1,500 structured events or 5 MiB, with an 8 MiB total local-storage safety boundary. Reaching any cap marks the record truncated, pauses collection, changes the in-page state to LIMIT, and requires Stop & Review before another session.

Privacy and redaction model

Before capture

The start confirmation names the tab, site scope, URL policy, data exclusions, retention behavior, and cross-origin pause rule. Recording begins only after the user confirms.

Before storage

The content recorder constructs the smallest semantic event it can. The background controller validates and sanitizes again before assigning sequence order and writing locally.

Before export

The user reviews the timeline, adds or edits the issue summary, deletes unwanted sessions, and explicitly downloads JSON or copies Markdown. No provider, webhook, MCP host, or network destination receives it automatically.

Risky surface v1.8 rule User-visible result
Passwords and sensitive inputs Ignore all values. Suppress labels/text when a target is inside a password, payment, one-time-code, or explicitly private control. “Changed protected input — value not recorded.”
URL secrets and identifiers Keep origin and pathname. Remove the complete query string and complete fragment before local storage. /callback plus a query/fragment redaction marker
Visible target text Cap length, collect text only from button/link-like controls, and prefer role/accessibility labels. Never read text-field contents. “Clicked button ‘Save item’.”
Cross-origin frames Do not attempt to pierce browser security boundaries. Record only the safe top-level interaction or that an unavailable frame was involved. “Interacted with embedded frame — details unavailable.”
Protected browser pages Do not inject. Record a pause/boundary event if the browser reports navigation, and explain that recording is unavailable. “Session paused on a protected page.”
Retention Local until deleted, with per-session deletion, clear-all, a latest-20-session limit, and 1,500-event, 5 MiB per-session, and 8 MiB total soft limits. Feedback Sessions shows date, duration, event count, status, summary, and Delete.

Export contract

Feedback Session JSON

Versioned session metadata, ordered sanitized events, privacy declarations, redaction markers, gap/interruption markers, and truthful truncation state.

Copied Markdown

A concise human-readable path with timestamps, route changes, semantic targets, issue summary, privacy exclusions, and actual capture gaps.

Existing evidence

Element, Visual, Region, History, AI Bundle, and MCP exports retain their current compatibility. Direct linkage into Feedback Sessions is a later additive change.

The export must distinguish observed, redacted, unavailable, and truncated evidence. A coding agent should be able to reconstruct the path without assuming that an omitted field was empty or that a paused interval was recorded.

Release gates

Approve the scope and language

Confirm “structured Feedback Session timeline” as the v1.8 product. WebM, audio, network inspection, console capture, multi-tab following, and broad host access remain excluded.

Prove the browser lifecycle

Validate the implemented start → interaction → same-origin full navigation → re-injection → SPA navigation → pause/resume → stop path in both unpacked Edge and Chrome.

Lock the schema and redactors

Add compatibility tests for legacy feedback items, deterministic event ordering, duplicate suppression, URL sanitation, selector/label sanitation, protected inputs, and cap handling.

Complete repo checks

Run npm test, npm run check, package verification, and git diff --check. These prove source/package contracts, not browser behavior.

Complete manual runtime proof

Load the exact unpacked v1.8 source in the active browser profile and complete the checklist below. Also re-test Element and Region modes per the repository contract.

Update public truth before upload

Match the privacy policy, Store data-use disclosures, permission justification, README, changelog, screenshots, package version, and actual behavior. Read the live Store state before replacing any in-review package.

Manual test checklist

  • Start requires an explicit click and shows the target tab, origin, URL policy, and exclusions.
  • The action badge and popup show recording, elapsed time, event count, scope, pause, and stop.
  • Only one active session can exist; a second start offers to return to or stop the current session.
  • Click a button and link; confirm semantic target data is useful and bounded.
  • Type email, password, one-time code, free text, and payment-like data; confirm no printable keys or values are stored.
  • Change checkbox, radio, select, and text input; confirm only safe change intent is recorded.
  • Submit a form; confirm form values and serialized form data are absent.
  • Scroll repeatedly; confirm events coalesce into a small number of final checkpoints.
  • Use Enter, Escape, Tab, arrows, and Space; confirm only the allowlisted key name is stored.
  • Perform same-origin full navigation and confirm the next interaction is recorded without duplicates.
  • Use history.pushState, fragment navigation, reload, and back/forward; confirm distinct ordered route events.
  • Trigger a failed page load and confirm a navigation-error event without sensitive network detail.
  • Cross to a new origin; confirm interaction recording pauses visibly and does not silently inject.
  • Resume on the new origin only through an explicit user gesture; confirm the gap is preserved in export.
  • Open a link in a new tab; confirm the session stays on its original target unless the user explicitly transfers it.
  • Switch away from and back to the target tab; confirm no events are collected from the other tab.
  • Visit a protected browser page, hosted PDF, local PDF, and cross-origin iframe; confirm graceful boundary events.
  • Pause and resume; confirm no page interactions are stored during the paused interval.
  • Reload the extension or restart the browser mid-session; confirm an honest interrupted/resumed state with no fabricated continuity.
  • Create Element, Visual, and Region feedback during a session; confirm each item links once and remains valid in ordinary History.
  • Stop and review; delete one event, edit the session name/marker note, and delete a whole session.
  • Export Feedback Session JSON and copy Markdown; confirm stable ordering, redactions, gaps, summary text, and privacy declarations.
  • Hit the 1,500-event, 5 MiB session, and 8 MiB local-storage safety caps in test fixtures; confirm the visible LIMIT state, automatic pause, and truthful truncated marker.
  • Confirm there are no network requests, telemetry calls, microphone/webcam access, or continuous screenshots.
  • Re-test ordinary Element and Region mode in unpacked Edge/Chrome, then run the repo and package gates.

WebM later: proof required before roadmap commitment

Technical proof

Capture survives the real journey

Prove one user-triggered stream across reload, same-tab cross-origin navigation, tab mute/audio routing, pause/resume, browser sleep, extension reload, and stop. Test Chrome and Edge separately.

Privacy proof

Users understand pixels are sensitive

Video may contain typed values, private customer data, notifications, and secrets that structured redaction would omit. Require a separate consent screen, obvious indicator, no audio by default, and pre-export preview.

Storage proof

Bounded capture without data loss

Choose chunking, temporary storage, maximum duration/size, recovery after interruption, explicit download, and deletion. Never keep an unbounded WebM blob in chrome.storage.local.

Only then choose: WebM as an optional supplement linked to the structured timeline, or no video at all. The timeline remains the durable source for search, export, agent handoff, and redaction.
